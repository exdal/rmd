# Compiler prelude

This crate owns the DM definitions compiled ahead of every project and the intrinsic ABI attached
to those definitions.

- `BYOND_VERSION` is the newest supported BYOND release. `build.rs` turns it into the `DM_VERSION`
  and `DM_BUILD` defines, which load ahead of `core.dm`. The stddef update workflow rewrites it
  together with `stddef.dm`.
- `core.dm` defines the root `/datum`, `/list`, and `/alist` types. It is mandatory and remains
  enabled when the optional prelude is disabled.
- `stddef.dm` contains generated BYOND standard definitions. It is written by BYOND itself, so it
  holds only defines and consts. **Do not edit it by hand.**
- `stddef_ext.dm` carries the types that go with those defines: the atom tree, `/image` and
  `/mutable_appearance`, `/client`, `/savefile`, the geometry types, `/world`, the global procs, and
  the native hooks. This is BYOND's own surface, so anything demir invents belongs elsewhere.
- `demir.dm` contains only demir's own: the `__DEMIR__` compatibility defines, the lighting and
  appearance schema it adds to `/atom` and `/image`, `/datum/demir` and its baking hooks, and the
  rebaking procs.
- `imgui.dm` declares the editor panel's `imgui_*` widgets, which only a profile's `ui()` hook may
  call.

They load in that order, so `stddef_ext.dm` may use anything `stddef.dm` defines and `demir.dm` may
reopen any type `stddef_ext.dm` declared.

`build.rs` reads intrinsic markers from `core.dm`, `stddef_ext.dm`, `demir.dm` and `imgui.dm`,
validates their numeric IDs, and generates the Rust `Intrinsic` enum used by semantic analysis, IR,
code generation, and the VM.
