# Compiler prelude

This crate contains the DM declarations that demir loads before project source. It also defines the
intrinsic ABI that connects DM procedures to the compiler and virtual machine.

The files load in this order:

1. `BYOND_VERSION` names the newest supported BYOND release. `build.rs` converts it to the
   `DM_VERSION` and `DM_BUILD` defines.
2. `core.dm` declares the required `/datum`, `/list`, and `/alist` root types.
3. `stddef.dm` contains definitions generated by BYOND. Do not edit this file by hand.
4. `stddef_ext.dm` declares the BYOND types, global procedures, and native hooks that use those
   definitions.
5. `demir.dm` declares the appearance profile interface, its lighting schema, and its bake helpers.
6. `imgui.dm` declares the widgets that a profile can use from its `ui()` hook.

This order lets later files reopen types from earlier files. `core.dm` remains active when a caller
disables the optional standard prelude. Projects can omit an appearance profile.

`build.rs` reads intrinsic markers from the maintained DM files. It checks their numeric IDs and
generates the Rust `Intrinsic` enum. Semantic analysis, IR generation, code generation, and the
virtual machine share that enum.

See [`docs/demir.md`](../docs/demir.md) for the compiler and appearance-baking architecture.
